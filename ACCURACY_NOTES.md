# Реальная LLM-оценка: исправления и ограничения

Изолированная версия для интеграции. Внешние API не вызывались, реальные данные не отправлялись.

- Общий JSON-контракт evaluations для Gemini, Groq и Ollama: устранён конфликт «array» vs json_object.
- Промпт соответствует официальным исключениям и шкалам, содержит случаи для калибровки (не Ground Truth).
- Проверяются полный набор ID, тип boolean, дискретные ступени, причины N/A.
- Подтверждающая цитата обязана буквально встречаться в указанной реплике. Время берётся из источника; неподтверждённая цитата блокирует итог.
- Ошибки провайдера/JSON не дают HTTP 500 и не переключают локальную оценку на облако. Секреты не выводятся.
- GROQ_MODEL и OLLAMA_MODEL настраиваются через env; у Ollama температура 0 и seed 42.
- Без работающей модели оценки не выдаются. Это существенно для отбора: перед показом необходимо подключить локальную Ollama или явно разрешённый облачный провайдер и проверить реальный end-to-end запуск.

## Проверка
16 unit/integration tests проходят, обращения провайдеров замоканы. Это проверка контракта, НЕ точности AI. Результат на неизвестных 10 транскриптах неизвестен без Ground Truth.

Сравнение полученных результатов с разметкой локально:
`python scripts/compare_ground_truth.py truth.json predictions.json`
Метрики: exact-match критериев, coverage, MAE итогов и флаг ошибок. Отказы считаются ошибкой в exact-match, MAE показывает количество доступных итогов. Эти метрики не заявлены как официальные метрики организаторов.

Сопоставление цитат подтверждает наличие фрагмента, но не логическую правильность вывода. Нужен размеченный RU/KZ/EN набор, особенно для N/A и грубых ошибок. Полноту и правильность финансовой консультации нельзя доказать без регламентов; промпт требует ручную проверку при недостатке контекста.
