# Ответы для защиты CQA

## Что делает проект?

Пользователь загружает диалог, выбирает сохранённый чек-лист и получает оценку работы оператора. Для каждого критерия видны ответ, баллы, вес, объяснение и подтверждающие сообщения. Спорный критерий можно оспорить; проверяющий принимает решение с причиной, после чего код пересчитывает итог и сохраняет исходную оценку.

## Почему результат можно проверить?

Обоснование связано с существующими ID реплик. При отсутствии действия указывается проверенный диапазон. Сервер отклоняет несуществующие доказательства, неправильные типы, недопустимые ступени и запрещённое N/A. Снимок чек-листа хранится вместе с оценкой. Такая проверка подтверждает структуру и ссылки, но сама по себе не доказывает правильность суждения модели.

## Что происходит при N/A?

У критерия должно быть разрешение N/A и объяснение применимости. Его вес исключается из знаменателя. Например, после исключения весов 15 и 20 остаётся 65; потеря 5 даёт 92,31. Отсутствие применимых положительных весов означает отсутствие итогового балла. Грубая ошибка отмечается отдельно.

## Можно ли заменить критерий на защите?

Да. В редакторе изменяются текст, тип, вес, шкала и N/A. Сохранение создаёт новую версию, которую выбирают при следующей оценке. Перезапуск и редактирование кода не нужны. Для новой автоматической оценки необходима доступная квота модели.

## Почему бот не считается оператором?

Роли сохраняются. В инструкции модели явно указано оценивать только оператора; бот, клиент и системные события являются контекстом. Для демонстрации подготовлен вымышленный пример с командой внутри реплики бота. Наличие инструкции не заменяет отдельную проверку устойчивости модели на независимых примерах.

## Насколько точна модель?

На трёх опорных примерах RU/KZ/EN после уточнения N/A совпали 24 из 24 ответов по критериям. Эти примеры использовались при настройке, поэтому это регрессия, а не независимая точность. В полном DEV-прогоне успешно сохранено 11 оценок; завершение остановлено лимитом API. Разметки организаторов для расчёта точности у команды пока нет.

## Что работает, если API недоступен?

Просмотр сохранённых результатов, четыре явно подписанные учебные фикстуры, ручная оценка, редактор, апелляция, решение и экспорт. Ошибка API не превращается в низкую оценку оператора. На защите нужно назвать источник каждого результата: модель, ручной разбор или учебный сценарий.

## Где данные и ключ?

На компьютере — `data/state.json`; на публичном сайте — D1 с раздельными сессиями посетителей. Презентация хранится в R2. Ключ находится на сервере и не включается в браузерный код и Git. Для переноса данных между устройствами есть экспорт JSON. Корпоративная ролевая модель и совместное пространство сотрудников не входят в текущий демонстрационный режим.

## Поддерживаются ли звонки?

Да: транскрипт, исходные ISO-метки времени, аудиоплеер и ссылка на запись. При известном начале аудио возможен переход к позиции. Для прослушивания нужны действующие исходные ссылки. Модель получает только текст; для добавленного аудиокритерия дикции/интонации потребуется отдельный анализ звука.

## Сколько стоит оценка?

В последней трёхъязычной регрессии средняя расчётная цена успешного вызова gpt-6-luna — около $0,00042, время — 5,94 с. Стоимость зависит от токенов и тарифа, а диагностические и повторные вызовы учитываются отдельно в фактическом счёте. Название модели, usage и примерная цена сохраняются с результатом.

## Как связать с Dynamics 365?

Интерфейс написан отдельно на HTML/CSS/JavaScript и работает через JSON API. Это позволяет адаптировать его как HTML-компонент. Полная интеграция с Dynamics 365 в руководстве не требовалась и в этом прототипе не заявляется.

## Что остаётся до полной приёмки?

Сверка с отдельным PDF критериев организаторов, достаточная квота API, независимая проверка качества, контрольный group_id и выполнение контрольного задания. Команда должна передать ссылку организаторам, подтвердить доступность репозитория и зафиксировать финальный коммит до стоп-кода.

## Как оценена готовность?

Самооценка прототипа — 8/10: основной цикл, интерфейс, хранение и демонстрация реализованы, тесты проходят. Десять баллов не заявляются из-за ограниченной независимой проверки модели, незавершённого полного прогона и внешних материалов приёмки. Это самооценка команды, не прогноз решения жюри.
