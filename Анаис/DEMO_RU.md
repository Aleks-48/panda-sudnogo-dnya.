# Панды судного дня — защита за 5 минут

## Подготовить перед выступлением

1. Запустить приложение и открыть «Обзор и демонстрация».
2. Проверить зелёный статус реального запроса к модели. Проверка использует API-кредиты.
3. Нажать «Новый учебный прогон»: появится свежая исходная фикстура для апелляции. Предыдущая история сохранится.
4. Открыть презентацию presentation/Pandy_sudnogo_dnya_CQA.pptx. На каждом слайде логотип и название команды. Заметки докладчика содержат источники и пояснения.
5. Для API-примера выбрать p1-ru-001 и последнюю оценку модели: 93,75. Для N/A показать «Идентификация». Для апелляции использовать только явно учебный demo-appeal-ru.

## Роли и тайминг

### 0:00–0:45 — Александр, слайды 1–2

«Мы — Панды судного дня, студенты Кокшетауского университета им. Шокана Уалиханова. Разработали CQA: оценка работы оператора по настраиваемым критериям и пересмотр спорного результата. В DEV 65 диалогов на трёх языках, чаты и звонки».

### 0:45–2:20 — Анаис, слайды 3–5 и карточка диалога

«Восемь критериев загружаются из конфигурации команды. Числовые шкалы дискретные. N/A исключается из суммы применимых весов. По каждому критерию есть ответ, объяснение и доказательство».

Открыть последнюю API-оценку p1-ru-001. Показать N/A, итог и переход к m9. Отметить, что исходный чек-лист сохраняется вместе с оценкой. Формула на слайде 4 относится к отдельному учебному примеру 92,31, а 93,75 на слайде 5 — фактический результат конкретного API-вызова.

### 2:20–3:20 — Александр, слайд 6 и апелляция

Открыть demo-appeal-ru. Сразу назвать его учебной фикстурой с намеренно заниженным c7. «Оспорить оценку» у «Завершение», комментарий: «В m3 есть итог, помощь и прощание». Во вкладке «Апелляции» принять решение: изменить на «Да», причина: «Проверено по m3». Открыть карточку и показать исходные 92,31 и финальные 100.

### 3:20–3:50 — Александр, слайд 7

«18 тестов прошли. Реальные вызовы на RU/KZ/EN возвращают восемь результатов. В последней серии среднее время около 4,8 секунды, примерная цена трёх оценок около $0,0012. Это проверка интеграции на небольшой выборке. Применимость N/A ещё требует калибровки по разметке команды».

### 3:50–5:00 — Анаис, слайд 8 и редактор

Изменить формулировку критерия или добавить девятый через UI. Пример: «Конкретный следующий шаг», тип Да/Нет, вес 5, N/A разрешён, правило: «Да — оператор дал понятный следующий шаг. N/A — клиент не сформулировал запрос». Сохранить новую версию, выбрать её в карточке и запустить оценку. Дождаться результата с новым критерием. Не редактировать код.

Финальная фраза: «Результат можно проверить по репликам, оспорить и пересчитать. Для финального прогона ждём контрольные диалоги организаторов».

## Резерв при отсутствии сети

Показывать заранее сохранённые API-результаты и учебные фикстуры. Не выдавать ручную фикстуру за ответ модели. Смена критерия через UI работает без интернета; новая автоматическая оценка требует доступа к модели.

## Известные ограничения

Отдельный PDF критериев не предоставлен для независимой сверки. В малой выборке есть расхождение модели и ручного разбора по применимости c2. Полный DEV не размечен командой. Аудиоссылки в GitHub исключены: на этом компьютере остаются в локальном DEV, на другом нужно импортировать исходный набор. Ключ хранится только локально и имеет срок действия.
