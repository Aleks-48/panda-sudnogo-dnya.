# CQA Workbench — Анаис

Прототип Conversation Quality Analytics: HTML/CSS/JavaScript, Node.js, без npm-зависимостей и регистрации.

## Запуск

Требуется Node.js 22.9+; проверено на 24.22.

```powershell
cd Анаис
node --env-file-if-exists=.env server.mjs
```

Открыть http://127.0.0.1:3000. В Windows можно запустить START_CQA.cmd. Если запускаете из папки «Анаис», команду cd пропустить. PORT меняет порт, DATA_DIR — каталог локального состояния. Слушает только 127.0.0.1.

## Чек-лист: 8 критериев

По умолчанию автоматически загружается checklist.official.json, преобразованный из official_checklist.json в корне командного репозитория:

| Критерий | Вес | Ответ |
|---|---:|---|
| Установление контакта | 10 | Да/Нет |
| Выявление потребности | 15 | Да/Нет/N/A |
| Идентификация | 20 | Да/Нет/N/A |
| Корректная и полная консультация | 20 | 0/5/10/15/20 или N/A |
| Эмпатия и клиентоориентированность | 15 | Да/Нет |
| Управление диалогом, скорость и грамотность | 15 | 0/4/7/10 |
| Завершение | 5 | Да/Нет/N/A |
| Грубые ошибки | 0 | Да/Нет, отдельный флаг |

Сумма весов — 100. Сохранение в редакторе создаёт новую версию. Можно менять формулировки, тип, вес, N/A, шкалу, дискретные ступени, секцию и условие флага грубой ошибки. Изменение критерия применяется без редактирования кода. Результаты хранят снимок своей конфигурации. Старые учебные версии и оценки сохраняются при обновлении.

Источником конфигурации служит файл команды. Отдельный PDF критериев не предоставлен, независимая сверка с PDF организаторов не выполнена. Поле «Основной чек-лист команды» не является утверждением о такой сверке.

## Расчёт

Boolean нормализуется в 0/1, numeric — (value-min)/(max-min). Итог = 100 × сумма(norm × weight) / сумма применимых весов. N/A исключаются из знаменателя. Результаты секций считаются отдельно внутри секции. Округление до двух знаков по текущей конфигурации (редактируется). Нет применимого положительного веса — итог null, в UI «—». Ответ «Да» на c8 отмечает грубую ошибку, но не обнуляет балл; при пересмотре на «Нет» флаг снимается. Для числовых ступеней сервер отклоняет промежуточные значения.

## Что работает

Импорт JSON и получение набора по group_id, выбор RU/KZ/EN, поиск, чаты/звонки, исходные timestamps. Карточка показывает ответ, вес, эффективный вес, вклад, объяснение, доказательства и проверенный диапазон. Ссылки приводят к реплике; при известном начале аудио — к позиции записи. Есть ручная оценка, автоматический одиночный/пакетный запуск, история, подача апелляции, решение с причиной, пересчёт и экспорт.

Три синтетических диалога DEV на RU/KZ/EN разобраны вручную по восьми критериям: examples/manual-review.json. Они автоматически добавляются как явно помеченные ручные разборы только при совпадении ID и SHA-256 транскрипта. Это не разметка организаторов и не проверка качества API-модели; требуется подтверждение командой. В каждом примере итог 92,31: c2/c3 неприменимы, c7 не выполнен — одного прощания без итога или дальнейшей помощи недостаточно.

## Подключение модели

Скопировать .env.example в .env, заполнить параметры и перезапустить сервер. Ключи только на сервере; не публиковать .env. Поддерживаются:

- Совместимый Chat Completions API: LLM_PROVIDER=compatible, LLM_URL, LLM_MODEL, LLM_API_KEY.
- Gemini: LLM_PROVIDER=gemini, GEMINI_API_KEY, GEMINI_MODEL (либо LLM_MODEL).
- Groq: LLM_PROVIDER=groq, GROQ_API_KEY, GROQ_MODEL (либо LLM_MODEL).
- Локальный сервер: LLM_PROVIDER=ollama, LLM_URL=http://127.0.0.1:11434/v1/chat/completions, LLM_MODEL=<установленная модель>. Ключ для loopback-адреса не требуется.

Имена моделей не зашиты: укажите доступную модель своего провайдера/локального сервера. Ollama/модель не устанавливаются автоматически. Сохранённая конфигурация не доказывает доступность сервиса: реальный вызов проверяется при оценке. На диалог выполняется один вызов, без скрытых повторов. Невалидный ответ или сбой не сохраняются как плохая оценка оператора. Транскрипт трактуется как данные, команды внутри него не меняют инструкции.

Для платного API задать INPUT_PRICE_PER_MILLION и OUTPUT_PRICE_PER_MILLION по тарифу провайдера. Карточка показывает usage, время и рассчитанную стоимость; без тарифов стоимость не определена. Для сдачи указать фактическую модель и стоимость полного вызова. Выполнены небольшие реальные API-проверки; локально подключена gpt-6-luna, проверена на трёх языках. Ключ не включён в репозиторий.

Модель получает текст, не звук. В текущих восьми критериях отдельной оценки интонации/дикции нет. Если организаторы добавят аудиокритерий, нужно подключить анализ звука; транскрипт его не заменяет.

## Данные

65 транскриптов DEV: 35 RU, 15 KZ, 15 EN; 60 чатов, 5 звонков. В GitHub-копии подписанные ссылки исключены; audio_url=null и указана причина. Исходные локальные данные не перезаписываются. Для восстановления прослушивания импортируйте исходный DEV: обновление аудиометаданных разрешено при неизменном транскрипте, языке и канале. Изменение текста под существующим ID отклоняется, чтобы сохранить корректность доказательств.

DATASET_URL в .env — подписанная ссылка API из PDF. UI «Импорт данных» принимает group_id контрольного набора. Также поддержан JSON-файл: массив, {records:[...]} или {data:{records:[...]}}. API-ошибки показываются пользователю. Результаты и история сохраняются атомарно в data/state.json. Один процесс сервера; для промышленной многопользовательской работы нужна БД с транзакциями.

examples/state.example.json — архив прежней учебной ручной оценки. Он не загружается автоматически и не заменяет актуальные восемь критериев.

## Проверка

```powershell
node --test
```

18 тестов: арифметика/N/A/шкалы/доказательства, сквозная апелляция и сохранение, сохранение старой истории при миграции, модельный адаптер на локальном имитаторе, грубые ошибки и три ручных разбора. Имитатор проверяет интеграцию, а не интеллект реальной модели.

## Обзор, демонстрация и презентация

Стартовая вкладка показывает подключение модели, состояние набора и последние API-оценки. Есть фильтры по языку, каналу и наличию оценки, CSV-экспорт и остановка пакетной обработки после текущего запроса.

«Новый учебный прогон» создаёт четыре свежие фикстуры, сохраняя предыдущую историю: апелляция 92,31→100, N/A на KZ, грубая ошибка на EN и контекст бота. Учебные результаты не выдаются за ИИ. Для защиты есть presentation/Pandy_sudnogo_dnya_CQA.pptx и DEMO_RU.md; презентация также скачивается из приложения.

Реальные проверки: docs/TEST_RESULTS_RU.md и examples/live-test-report.json. Для повторения запустить `npm run test:live` при работающем локальном сервере. Команда выполняет несколько платных запросов и использует настроенный ключ; секреты не выводятся.

## Что ещё зависит от внешнего доступа

Качество модели на полном DEV требует разметки и калибровки N/A. Нужны сверка с PDF организаторов, контрольный group_id и время старта. На этом компьютере автоматическая оценка работает; на другом компьютере требуется свой локальный .env. Исходный ключ не передаётся через GitHub. Полная приёмка организаторами не заявляется.
