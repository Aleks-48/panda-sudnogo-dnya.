# CQA Workbench

Локальный прототип Conversation Quality Analytics для кейса Freedom Broker. Интерфейс на HTML/CSS/JavaScript, сервер Node.js, без установки npm-зависимостей и регистрации.

## Запуск

Требуется Node.js 22.9+ (проверено на 24.22).

```powershell
node --env-file-if-exists=.env server.mjs
```

Открыть http://127.0.0.1:3000. В Windows можно также дважды нажать START_CQA.cmd. Если Node не добавлен в PATH, использовать полный путь к node.exe. Порт можно изменить переменной PORT. Приложение слушает только локальный компьютер. Для совместного или публичного размещения потребуются отдельная настройка доступа и хостинга.

```powershell
node --test
```

Все 9 тестов проходят. Они проверяют веса, шкалы, N/A, ссылки на доказательства, импорт, версии, апелляцию, пересчёт, сохранение на диск, а также адаптер модели на локальном имитаторе (без платных вызовов). Тестовые данные пишутся в tmp/ отдельно от рабочего набора. В браузере проверены открытие DEV, ручная оценка и переход к доказательству. Качество реальной модели не проверено.

## Что работает

- Импорт JSON из файла; получение набора по group_id через сервер.
- Список и поиск по диалогам, фильтр RU/KZ/EN; 60 чатов и 5 звонков из DEV загружены в локальное data/dev.json.
- Редактор критериев: название, инструкция, вес, тип да/нет или числовой, шкала, N/A, секция, округление.
- Сохранение новой версии чек-листа. Оценка хранит снимок конфигурации.
- Автоматическая оценка через настраиваемый API с проверкой структуры ответа и ссылок на доказательства. Одиночный и последовательный пакетный запуск.
- Отдельная ручная оценка; всегда помечена как ручная.
- Карточка диалога, переход к сообщению-доказательству, проверенный диапазон для отсутствующего действия, причина N/A.
- Взвешенный итог, перераспределение веса N/A, результаты секций, флаг грубой ошибки.
- Плеер звонка и ссылка на запись. Для точного перехода по ISO-метке необходимо указать известный момент начала записи в карточке; без него показывается сообщение транскрипта.
- Апелляция с комментарием, подтверждение/изменение оценки с причиной, пересчёт, сохранение исходной и финальной оценки.
- JSON-экспорт результатов и атомарная запись локального состояния.

## Подключение автоматической оценки

Скопировать .env.example в .env. Вписать LLM_URL, LLM_MODEL и LLM_API_KEY для API, поддерживающего Chat Completions и JSON-ответ. Перезапустить сервер. Секрет остаётся на сервере и не отдаётся интерфейсу. Без конфигурации автоматический запуск отключён, ручная оценка и остальные функции работают.

Модель выбирается командой. В этой поставке платный API не подключён, платных вызовов не выполнялось. Для итоговой сдачи указать реальную модель и стоимость. Задать INPUT_PRICE_PER_MILLION и OUTPUT_PRICE_PER_MILLION по тарифу выбранного провайдера. Карточка показывает длительность, usage и рассчитанную стоимость одного вызова. Сейчас на оценку выполняется один вызов, без скрытых повторов. Если тарифы не заданы, выводится «Стоимость не настроена», а не бесплатная оценка.

Текст диалога передаётся выбранному поставщику только при автоматическом запуске. Сам код адаптера можно заменить локальной моделью с совместимым API. Модель не получает звук; критерии дикции и интонации требуют отдельного аудиомодального оценщика или ручной проверки записи. Работа по одним транскриптам не подтверждает выполнение таких критериев.

## Данные организаторов

DEV скачан по встроенной ссылке со страницы 3 PDF. Состав проверен: 65 записей, 35 RU / 15 KZ / 15 EN, 60 agent chat / 5 voice call. Приложение подхватывает data/dev.json при первом старте, если ещё нет data/state.json. Данные и подписанные ссылки исключены из Git.

Для загрузки контрольного набора задать DATASET_URL в .env (исходный адрес API из PDF), затем в UI «Импорт данных» ввести выданный group_id. Сервер заменяет только этот параметр. Можно импортировать сохранённый ответ API через JSON-файл. Поддерживаются массив записей, {records:[...]} и {data:{records:[...]}}. ID и исходные timestamps сохраняются. Изменённый диалог с уже существующим ID не перезаписывается, чтобы не разрушить историю доказательств.

## Важное ограничение: официальный чек-лист отсутствует

Предоставлен только Student Guide; он ссылается на отдельный PDF с восемью критериями. В поставке есть явно помеченный учебный шаблон из двух критериев. Он не является реконструкцией официального чек-листа.

После получения PDF перенести все восемь критериев через UI либо импортировать JSON по образцу checklist.example.json. Проверить веса, шкалы, N/A, грубые ошибки, секции и округление. Отметку «Сверено с официальным PDF» ставит проверяющий, она сама по себе не подтверждает правильность конфигурации.

Текущая формула: boolean нормализуется в 0/1, numeric в (value-min)/(max-min); итог = 100 × сумма(norm × weight) / сумма применимых весов. N/A исключается из знаменателя. При нулевой сумме применимых весов итог null (в UI — «—»). Секции считаются по той же формуле внутри секции. Итог округляется один раз до заданного числа знаков. Грубая ошибка отмечается отдельно, без дополнительного автоматического штрафа. Если официальный чек-лист требует другой формулы, ограничений или штрафа, адаптировать core.mjs и тесты до сдачи.

## Структура

- core.mjs — валидация, импорт, расчёт.
- server.mjs — HTTP API, модель, версии, хранение, апелляции.
- public/ — интерфейс без привязки к конкретному CRM SDK; адаптеры загрузки и сохранения можно заменить при переносе в Dynamics 365.
- test/ — проверка расчёта и сквозного серверного сценария.
- data/ — приватные локальные данные; не коммитятся.
- PLAN_CQA_RU.md — план на 24 часа и матрица требований.
- DEMO_RU.md — сценарий пяти минут и фактический статус готовности.

Хранилище — локальный JSON с атомарной заменой файла; один процесс сервера. Это выбор для прототипа, а не многопользовательская промышленная БД. Перед переносом заменить на БД с транзакциями и контролем одновременных изменений.

## Перед сдачей

1. Получить официальный чек-лист и проверить расчёт.
2. Подключить модель, прогнать RU/KZ/EN и звонки, вручную сверить выборку. Серверные тесты не заменяют проверку качества модели.
3. Проверить ссылки на аудио и синхронизацию. Для аудиокритериев подключить анализ звука.
4. Создать открытый удалённый Git-репозиторий и передать ссылку организаторам. В этом окружении remote отсутствует; внешняя публикация не выполнена.
5. На T+23 получить контрольный group_id, обработать набор. На T+24 зафиксировать последний коммит.
