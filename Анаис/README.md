## Начальная конфигурация: восемь критериев

| Критерий | Вес | Допустимый ответ |
|---|---:|---|
| Установление контакта | 10 | Да / Нет |
| Выявление потребности | 15 | Да / Нет / N/A |
| Идентификация | 20 | Да / Нет / N/A |
| Корректная и полная консультация | 20 | 0 / 5 / 10 / 15 / 20 / N/A |
| Эмпатия и клиентоориентированность | 15 | Да / Нет |
| Управление диалогом, скорость и грамотность | 15 | 0 / 4 / 7 / 10 |
| Завершение | 5 | Да / Нет / N/A |
| Грубые ошибки | 0 | Да / Нет, отдельный флаг |

Сумма весов — 100. Число чек-листов не фиксировано: пользователь создаёт версии, а оценка хранит снимок применённых правил. Изменение текущего чек-листа не пересчитывает старую историю автоматически.

### Расчёт итогового балла

Для «Да/Нет» нормализованный ответ равен 1/0. Для числового ответа:

```text
нормализованный ответ = (ответ − минимум) / (максимум − минимум)
итог = 100 × Σ(нормализованный ответ × вес) / Σ(применимых весов)
```

N/A исключается из обеих сумм. В учебном примере веса 15 и 20 неприменимы: знаменатель равен 65. Потеря пяти баллов даёт `100 × 60 / 65 = 92,31`. После обоснованного пересмотра — 100. Если применимых положительных весов нет, итог отсутствует, а не становится 100. Флаг грубой ошибки выводится отдельно и не обнуляет результат. Секции считаются внутри своих применимых весов; округление задаётся конфигурацией, по умолчанию два знака.

## Модель, доказательства и стоимость

В проверках использована **OpenAI `gpt-6-luna`**. Модель получает выбранный чек-лист и текст транскрипта; итоговый балл вычисляет код. Сервер проверяет типы, ступени, N/A, полноту ответа, существование доказательств и границы диапазонов. Невалидный ответ API не сохраняется как низкая оценка оператора.

После уточнения приоритета условий N/A повторены три опорных примера RU/KZ/EN: **24 из 24 ответов по критериям совпали с ручным разбором**, итог каждого — 92,31. Эти примеры участвовали в настройке инструкции: результат является регрессионной проверкой, а не независимой оценкой точности.

В этой серии среднее время составило **5,94 с**, средняя расчётная цена — **около $0,00042 за диалог**; сумма трёх успешных вызовов — $0,0012472. Использованные ставки: $0,10 за миллион входных и $0,50 за миллион выходных токенов. Фактический счёт зависит от длины диалога, тарифа и всех выполненных запросов. Приблизительная стоимость в карточке вычисляется из `usage`; диагностический запрос является отдельным вызовом.

Обычно выполняется один запрос на оценку. При кратковременном `429`/`503` предусмотрены до двух повторов с паузой; при длительном ограничении ожидание прекращается с понятным сообщением. Модель получает текст, **аудио в LLM не передаётся**. Анализ дикции/интонации потребует отдельного аудиоадаптера, если такой критерий будет выдан организаторами.

## Данные и хранение

| Версия | Хранилище | Доступ |
|---|---|---|
| На компьютере | `data/state.json`, каталог меняется через `DATA_DIR` | Данные локального процесса |
| Публичный сайт | Cloudflare D1: версии, оценки, диалоги, апелляции | Отдельные данные сессии посетителя |
| Презентация на сайте | Cloudflare R2 | Скачивание по кнопке |

Публичный сайт содержит только четыре придуманных учебных диалога. Рабочий локальный DEV и реальные звонки не включены в пакет публичной демонстрации. Импортированные посетителем записи сохраняются в его сессии; другой браузер получает другую сессию. Для переноса между устройствами предусмотрен экспорт JSON. В рамках демонстрации подача апелляции и проверка выполняются отдельными действиями в одной сессии; полноценное разграничение сотрудников потребует корпоративной авторизации.

Сессия определяется HttpOnly-cookie. При параллельном изменении данных сервер проверяет версию и сообщает о конфликте вместо молчаливой перезаписи. Ключ API хранится на сервере: в локальном `.env` или секрете хостинга; браузер и репозиторий его не получают. Локальный JSON-сервер рассчитан на один процесс; облачная версия использует транзакционные изменения D1.

DEV проверен локально: **65 записей = 60 чатов + 5 звонков; 35 RU + 15 KZ + 15 EN**. Все транскрипты непустые, у пяти исходных звонков есть аудиоссылки. Подписанные адреса не публикуются. Для прослушивания нужны исходный набор и действующие ссылки; точная синхронизация ISO-времени требует известного начала записи. Обновление аудиометаданных допускается при неизменных тексте, языке и канале; подмена текста под старым ID отклоняется.

## Проверки и воспроизводимость

**21 автоматический тест:** 18 у основного приложения и 3 у облачной версии. Проверяются расчёт и N/A, ступени шкал, доказательства, грубые ошибки, миграция истории, полный цикл апелляции, сохранение, адаптеры модели, разделение посетителей и ошибки импорта.

Полный автоматический прогон DEV запущен с разрешения владельца. **Успешно сохранены 11 из 65 оценок**; завершение остальных остановлено лимитом API. Кроме ограничений частоты, в первом проходе был один ответ, отклонённый проверкой доказательств. Поэтому утверждение «65/65 прошли» и процент точности на полном DEV не заявляются. Подробности и различие интеграционных проверок и оценки качества — [в отчёте](docs/TEST_RESULTS_RU.md).

```powershell
# В папке Анаис: тесты локального приложения, без платных вызовов
node --test test/*.test.mjs

# В папке hosting: тесты облачной версии, без платных вызовов
```

## Локальный запуск для разработчика

Для жюри достаточно ссылки выше. Для воспроизводимости локальная версия требует Node.js 22.9+; проверено на 24.22. У основного приложения нет внешних npm-зависимостей.

```powershell
git clone https://github.com/Aleks-48/panda-sudnogo-dnya..git panda-cqa
cd panda-cqa/Анаис
node --env-file-if-exists=.env server.mjs
```

Открыть `http://127.0.0.1:3000`. В Windows есть `START_CQA.cmd`. Если уже находитесь в «Анаис», переход в каталог не нужен. `PORT` меняет порт; сервер слушает только `127.0.0.1`.

Для собственных API-вызовов скопировать `.env.example` в `.env` и задать модель/ключ. Локальная копия не получает секрет опубликованного сайта. Поддерживаются совместимый Chat Completions API (`OPENAI_API_KEY` либо `LLM_API_KEY`), Gemini, Groq и локальный совместимый сервер. Настройки описаны в [.env.example](.env.example). Сам ключ не нужно отправлять команде или коммитить.

Для получения набора по `group_id` администратор задаёт `DATASET_URL` на сервере, используя подписанную ссылку из руководства. Публичная демонстрация не раскрывает эту ссылку. Альтернатива — импорт исходного JSON через UI: поддержаны массив, `{records:[...]}` и `{data:{records:[...]}}`. Контрольный идентификатор сообщает организатор.
